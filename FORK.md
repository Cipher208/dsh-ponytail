# Fork notes

This is a fork of [MengYuil/dsh-ponytail](https://github.com/MengYuil/dsh-ponytail) carrying a single fix,
made on 2026-10-11 against upstream `0.4.1` (commit `6a997e8`).

## The fix

`master` here adds one commit on top of upstream:

> **fix: emit a producer-owned message source kind**

## Why upstream breaks

DeepSeek Harness's V4 session format **retired** the shared `{ kind: 'plugin', plugin }` wrapper. Native
admission refuses it in every declared durable message slot
(`packages/session/session-format-v3-to-v4/src/message-sources.ts`), and the architecture note
*producer-owned message sources* states the rule: a message source's `kind` identifies the producer, and
message sources are merge-extensible through `MessageSourceMap` — there is no shared catch-all `plugin` kind.

Upstream writes that retired shape in **nine** places: the mode-switch notice, the `/ponytail default` and
`/ponytail reset` replies, and the plain-text deactivation notice. Because a refused event blocks the whole
buffered write for the session, the symptom is not a lost notice — it is the whole turn failing:

```
This turn failed: format v4 message requires a producer-owned source kind
```

and, in the host log, durable writes failing on retry:

```
session-persistence: background write for session "<id>" failed (buffered events retained)
session-projection-cache: interval write for "<id>" failed (cache stays stale)
```

Any session that switches mode is affected, and so is every later write in that session: `/ponytail off`
does not repair it, because the refused event is already in the buffer. Only a restart clears it, and what
was buffered is lost.

**The plugin passes DSH's compatibility gate regardless.** That gate compares the declared
`@deepseek-ai/dsh*` peer *ranges* against the runtime version; it never inspects what the plugin writes. A
plugin can declare no such peer, pass, and still emit a row the format refuses.

The always-on ruleset is **not** at fault: it is delivered through `ctx.systemPrompt.section`, which never
touches the message format. Only the notices are.

## The change

1. Declare the plugin's own kind the way first-party producers do (compare `packages/goal/.../domain.ts`):

   ```ts
   export interface PonytailMessageSource {
     readonly kind: 'ponytail'
   }

   declare module '@deepseek-ai/dsh-llm' {
     interface MessageSourceMap {
       ponytail: PonytailMessageSource
     }
   }
   ```

2. Write `{ kind: 'ponytail' }` in all nine injection sites.
3. Rebuild `lib/` and the declaration files from `src/` with `scripts/build-ui.mjs`, refreshing
   `dist-provenance.json`.

`kind: 'ponytail'` is accepted by the real admission gate. `plugin:ponytail` is accepted too, and is what the
harness's own V3→V4 migration would have assigned this plugin's historical rows; `ponytail` is used here
because the plugin declares it explicitly.

## Verifying

The fork ships no test for this. The check that was used, and that still applies:

```js
// drive the plugin's own `agent/pre-step` branch in a real Cordis context,
// then pass the message it returns through the real admission gate
import { assertV4RowAdmission } from '@deepseek-ai/dsh-session-format-v3-to-v4'

const row = { type: 'user/message', seq: 0, time: Date.now(), data: returnedMessage }
assertV4RowAdmission(row)   // throws before the fix, passes after
```

Run upstream's own checks to confirm nothing else moved:

```sh
node scripts/check-bundle.mjs
node scripts/verify-dist.mjs
node scripts/test-core.mjs
node scripts/test-regressions.mjs
```

## Syncing from upstream

```sh
git fetch upstream
git merge upstream/master      # re-check the nine injection sites afterwards
```

`lib/` here is derived from `src/` by `scripts/build-ui.mjs`. Upstream's own `lib/` is generated by
`scripts/sync-dist.mjs` from `packages/community/ponytail` inside a deepseek-harness checkout; that checkout
is not required for this fix, which is one literal and one declaration.

## Upstream

This fix is offered upstream. Until it lands there, installing upstream `0.4.1` on DSH `0.2.0-rc.2` or later
reproduces the failure above.
